# CodePilot — Multi-Agent Coding Platform

CodePilot is a terminal-based AI coding agent built with **DeepAgents** (LangChain/LangGraph). It polls a GitHub repository for issues, plans and implements a fix with a team of agents, verifies the fix in an isolated sandbox, and opens a structured pull request. Before any risky operation it asks a human, through a 4-panel **Textual** TUI.

> Codebasics AI Engineering Bootcamp, Capstone Assignment 01 (CodePilot). CodePilot is a fictional product built for learning purposes.

## What CodePilot does

- **Polls GitHub** every N minutes for open issues labelled `ai-assignable`, or unassigned issues below a complexity threshold. It skips issues already being processed, issues that already have an open CodePilot PR, and issues that failed in a recent session.
- **Accepts direct tasks** typed into the TUI (`i`).
- **Plans before coding.** The root Orchestrator classifies the issue (`bug_fix`, `feature_addition`, `dependency_update`, `documentation`, `config_change`), loads the matching Skill, writes a checklist with `write_todos`, and delegates to the `repo_explorer` and `implementation_planner` subagents through the DeepAgents `task` tool.
- **Implements and verifies in a sandbox.** It works on a per-issue copy of the repository: it applies the change, runs the test suite, retries at most 3 times (human approval is required after 2 failed test runs), and writes a diff preview to `working/proposed_diff.txt`.
- **Opens a pull request** after two human approvals, checking first that the base branch hasn't changed under it (merge-conflict detection).
- **Remembers:**
  - **working memory** per task
  - **episodic memory**, with session summaries persisted across restarts
  - **semantic memory**: lessons learned from merged PRs, stored in ChromaDB and retrieved for similar future tasks
- **Enforces guardrails:**
  - a NeMo Guardrails input rail
  - a declarative sandbox policy
  - read-only GitHub tools for the LLM
  - four human-in-the-loop gates

## Architecture

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Textual TUI:  [GitHub Issues] [Active Task] [Agent Logs] [Human Approval] │
└────────────────────────────────┬─────────────────────────────────────────┘
                                 │ issues from polling / direct task [i]
                                 ▼
                ┌──────────────────────────────────┐
                │ NeMo Guardrails input rail        │  blocks prompt injection, secret
                │ (before ANY text reaches an LLM)  │  exfiltration, rm -rf, approval bypass
                └────────────────┬─────────────────┘
                                 ▼
     ┌──────────────────────────────────────────────────────────────┐
     │ Orchestrator — root create_deep_agent()                       │
     │  classify issue → select Skill → choose retrieval strategy    │
     │  Repo Map (≤4000 tokens) + top-K files → DeepAgents VFS       │
     │  memory: last tasks (episodic) + top-3 lessons (semantic)     │
     │  tools: write_todos, task, read-only GitHubToolkit tools      │
     │  auto-summarization on root + every subagent                  │
     └──────┬───────────────────────────────┬───────────────────────┘
            │ task tool                     │ task tool
            ▼                               ▼
   ┌────────────────────┐        ┌─────────────────────────┐
   │ repo_explorer      │        │ implementation_planner  │
   │ (DeepAgents        │        │ (DeepAgents subagent)   │
   │  subagent)         │        │ ls / read_file / grep   │
   │ ls/read_file/grep  │        │ on the VFS              │
   │ on the VFS         │        │                         │
   └────────────────────┘        └─────────────────────────┘
            └──────────── validated "Handoff:" (paths only) ─────────┐
                                                                     ▼
     ┌──────────────────────────────────────────────────────────────┐
     │ Coder — separate deep agent with NO tools                     │
     │ proposes a JSON change set (relevance-first file context)     │
     └────────────────────────────┬─────────────────────────────────┘
                                  ▼
     ┌──────────────────────────────────────────────────────────────┐
     │ CoderWorkspace + SandboxPolicy (per-issue copy of the repo)   │
     │ applies edits (path + secret-file checks) → Test Agent runs   │
     │ the suite → retry ≤3, HITL after 2 failures → diff preview    │
     └────────────────────────────┬─────────────────────────────────┘
                                  ▼
     ┌──────────────────────────────────────────────────────────────┐
     │ PR Agent — PullRequestWorkflow (deterministic)                │
     │ merge-conflict check → HITL approvals → branch, commit, PR,   │
     │ labels, reviewer → merge monitor records a semantic lesson    │
     └──────────────────────────────────────────────────────────────┘
```

**Why the LLM agents never execute anything.** The LLM agents (Orchestrator, Repo Explorer, Planner, Coder) **reason and propose**; deterministic components (Test Agent, PR Agent) **execute**. No LLM ever holds a shell, a file-write tool, or a GitHub write tool, so every guardrail and approval gate is enforced in code and a prompt-injected model cannot bypass it. This is documented as design decision **S-2** in [`docs/tool-substitutions.md`](docs/tool-substitutions.md).

## How one issue flows through the system

These are the actual Agent Logs lines you will see (from `docs/assets/`):

```
[Memory] Episodic memory: loaded 1 previous session summary(ies); recently failed issues that will be skipped: none.
[polling] Skipping issue #3 because an open CodePilot pull request already exists.
[Guardrails] Issue #6 not sent to the LLM. Guardrails (nemo) BLOCKED [prompt_injection]: ...
[orchestrator] Retrieval strategy for issue #8 (documentation): keyword.
[orchestrator] Memory for issue #8: 0 past lesson(s) from semantic memory, 1 recent task(s) from episodic memory.
[orchestrator] Virtual filesystem seeded: /repo-map.md + 1 relevant file(s) ['src/calculator.py'].
[orchestrator] [Orchestrator] tool call: write_todos (6 item(s))
[orchestrator] [Orchestrator] tool call: task → repo_explorer: Explore the repository for ...
[orchestrator] [repo_explorer] tool call: read_file(file_path=/src/calculator.py, offset=0)
[orchestrator] [Orchestrator] tool call: task → implementation_planner: Create a minimal implementation plan ...
[orchestrator] [Orchestrator] response: Handoff: ...
[deepagents_coder_adapter] Coder context: 1 relevant file(s) from Repo Map retrieval loaded first ['src/calculator.py']
[Coder] Tests: PASSED (exit code 0)
[HITL] Waiting for human approval: publish_branch
[HITL] Waiting for human approval: create_pull_request_against_protected_branch
[PR Agent] Pull request created: https://github.com/venkatarepalli/codepilot-smoke-test/pull/9
```

The task state machine is `TRIAGED → EXPLORING → IMPLEMENTING → TESTING → PR_OPENED → DONE | FAILED`. Transitions are enforced in `src/codepilot/graph/lifecycle.py`.

## Setup

### Prerequisites

- **Python 3.11, 3.12 or 3.13**
- **Git**
- An **OpenAI** or **Google Gemini** API key
- A **GitHub account**, plus a **disposable test repository** that you own. Don't point CodePilot at a production repository.
- Windows PowerShell, macOS or Linux. The commands below are PowerShell, with bash equivalents.

### 1. Clone and create a virtual environment

```powershell
git clone https://github.com/venkatarepalli/codepilot-agent.git
cd codepilot-agent
py -3.13 -m venv .venv            # macOS/Linux: python3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1      # macOS/Linux: source .venv/bin/activate
python -m pip install --upgrade pip
```

### 2. Install

```powershell
python -m pip install -e .
python -m pip install "pytest>=8,<9" "pytest-asyncio>=1.3,<2" "pytest-cov>=5,<7" "ruff>=0.8,<1"
```

This installs DeepAgents, LangChain, the GitHub toolkit, ChromaDB, NeMo Guardrails and Textual.

### 3. Verify the install (offline: no API keys or network calls needed)

```powershell
python -m pytest -q
```

Expected result: all tests pass. On Windows, one symlink test is skipped unless Developer Mode is on.

### 4. Prepare the test GitHub repository

1. Create a repository, e.g. `codepilot-smoke-test`, with a small Python project and a passing `pytest` suite. CodePilot only opens a PR when the tests pass, so **the suite must pass on `main` before you start**.
2. Create three labels: **`ai-assignable`**, **`codepilot-generated`**, **`needs-review`**.
3. Create a **fine-grained personal access token** limited to that one repository, with these permissions:
   - **Contents:** Read and write (branch and commit)
   - **Pull requests:** Read and write
   - **Issues:** Read and write (reading issues and applying labels)
   - **Metadata:** Read
4. Open an issue and add the `ai-assignable` label, e.g. *"Add a Usage section to the README"*.

### 5. Configure `.env`

```powershell
Copy-Item .env.example .env       # macOS/Linux: cp .env.example .env
notepad .env
```

Fill in `LLM_PROVIDER`, `LLM_MODEL`, the matching API key, `GITHUB_TOKEN`, `GITHUB_REPOSITORY_OWNER`, `GITHUB_REPOSITORY_NAME` and `GITHUB_DEFAULT_BRANCH`. `.env` is git-ignored; never commit it. All options are described in [Configuration reference](#configuration-reference).

### 6. Start CodePilot

```powershell
python -m codepilot.runner
```

|---|---|

If the keys stop responding, **click inside the TUI window** to give it keyboard focus.

## Configuration reference

All settings are read from environment variables, or from `.env` in the project root. [`.env.example`](.env.example) contains every option.

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `LLM_PROVIDER` | yes | | `openai` or `google` |
| `LLM_MODEL` | yes | | e.g. `gpt-4.1-mini`, or a Gemini model available to your key |
| `OPENAI_API_KEY` | if openai | | OpenAI key |
| `GOOGLE_API_KEY` | if google | | Gemini key |
| `GITHUB_TOKEN` | yes | | Fine-grained PAT for the test repository |
| `GITHUB_REPOSITORY_OWNER` | yes | | e.g. `venkatarepalli` |
| `GITHUB_REPOSITORY_NAME` | yes | | e.g. `codepilot-smoke-test` |
| `GITHUB_DEFAULT_BRANCH` | no | `main` | Base branch for PRs (PRs to `main`/`master` require approval) |
| `CODEPILOT_POLL_INTERVAL_MINUTES` | no | `5` | Polling interval |
| `CODEPILOT_COMPLEXITY_THRESHOLD` | no | `7` | 1–10; unlabelled, unassigned issues must score below this |
| `CODEPILOT_REPO_MAP_TOKEN_BUDGET` | no | `4000` | Repo Map token budget |
| `CODEPILOT_REPO_MAP_TOP_K` | no | `10` | Relevant files returned by retrieval |
| `CODEPILOT_MEMORY_DIR` | no | `.codepilot/memory` | Where session summaries are stored |

Local state (Repo Map cache, ChromaDB, session summaries) lives in `.codepilot/`, which is git-ignored. Sandbox workspaces are created **outside** the checkout, in `../.<checkout-name>-codepilot-workspaces/`. To reset memory, delete `.codepilot/memory/sessions.jsonl` (episodic) or `.codepilot/memory/semantic/` (lessons).

## Safety model

Every layer fails closed. Details are in [`docs/guardrails.md`](docs/guardrails.md).

1. **NeMo Guardrails input rail** (`src/codepilot/guardrails/`). Every issue and direct task is screened before **any** LLM sees it. It blocks:
   - prompt injection
   - secret exfiltration
   - destructive shell requests (`rm -rf`, `curl … | sh`, `mkfs`, `dd`)
   - edits to `.env`, `*.pem`, `*.key`, `*.secret` and `*credentials*`
   - attempts to bypass approval or force-push

   It runs a deterministic Colang flow and Python action, so it makes no LLM calls and gives the same result every time. If NeMo is unavailable, the same rules run in Python.
2. **Read-only GitHub tools for the LLM.** The Orchestrator gets only the toolkit's read tools (`Get Issues`, `Get Issue`, `Read File`, `Search code`, …). `Delete File`, `Create/Update File`, `Create Pull Request` and `Set active branch` are never bound to any model.
3. **Sandbox policy** (`sandbox/policy.py`). It blocks:
   - `rm -rf`, `curl`, `wget` and `pip install`
   - shell control operators
   - paths outside the sandbox
   - writes to secret files

   `git push` requires approval.
4. **Human-in-the-loop gates** in the TUI:
   - publishing a branch
   - a PR to `main`/`master`
   - a change touching more than 5 files
   - `git push`
   - retrying after 2 failed test runs
5. **Merge-conflict detection.** If a changed file was edited on the base branch after CodePilot cloned it, the task fails with a TUI notice and nothing is pushed.
6. **Secrets.** `.env` is git-ignored, the token is passed to `git clone` through an environment header (never on the command line), and secret files are never copied into the agents' context.

## Design decisions and substitutions

The full write-ups, with reasons, alternatives and trade-offs, are in [`docs/tool-substitutions.md`](docs/tool-substitutions.md) and [`docs/design-decisions.md`](docs/design-decisions.md).

- **S-1: Sandbox.** The DeepAgents local sandbox backend is replaced by a per-issue workspace copy plus a declarative `SandboxPolicy`. `LocalShellBackend` executes on the host with no command filtering, and DeepAgents permissions cover file tools only, so neither can express the required command block-list.
- **S-2: Agents that execute are deterministic.** The Coder is a tool-less deep agent that returns a JSON change set. The Test Agent and PR Agent are deterministic components rather than `task`-spawned LLM subagents, so no LLM holds execute or write capabilities. `repo_explorer` and `implementation_planner` are real DeepAgents subagents.
- **D-1: Polling.** Polling uses the GitHubToolkit's `GitHubAPIWrapper` repository rather than the `Get Issues` tool. That tool returns plain text with only title and number (no labels, assignee or body), so `ai-assignable` and "unassigned" filtering would be impossible with it.
- **D-2: Coder context.** The Coder prompt contains file contents, because it must return complete replacement files. The files are chosen relevance-first from Repo Map retrieval, with a cap.
- **Summarization.** `create_deep_agent()` in DeepAgents 0.7 has no `summarization=` argument (passing one raises `TypeError`). The library installs `SummarizationMiddleware` on the root agent and every subagent; this is recorded as `ORCHESTRATOR_BACKEND_CONFIG["summarization"] = True` and verified by a test.

## Known limitations

- **Semantic lessons are only recorded for PRs merged while CodePilot is running.** The merge monitor tracks PRs from the current session.
- **Whole-file edits.** The Coder returns complete file contents rather than diffs. Deleting files isn't supported for publication.
- **Same delegation chain for every category.** Classification selects the Skill and the retrieval strategy; the subagent chain is the same for all categories.
- **Exported symbols for Python only.** The Repo Map extracts symbols only from Python files (via `ast`); other languages get language and path only.
- **Directory-level isolation.** The sandbox isolates by directory and policy, not by OS-level container. The whole repository is copied, not a subset, because a partial copy would break test imports.
- **Custom Skills registry.** Skills are a structured Python registry rather than DeepAgents `skills` SKILL.md files.
- **Two LLM providers.** OpenAI and Google Gemini only.
- **Self-review.** When the GitHub token belongs to the issue reporter, the reviewer request is skipped (GitHub forbids self-review); a warning is logged.

## Troubleshooting

| Symptom | Fix |
|---|---|
| TUI keys don't respond | Click inside the TUI window to give it focus |
| `pip install -e .` dependency conflict | Use Python 3.11–3.13 in a fresh virtual environment |
| Every issue is "skipped because an open CodePilot pull request already exists" | Merge or close those PRs, or open a new issue |
| Issue skipped as "FAILED in one of the last session(s)" | Expected (episodic memory). Fix the cause, then delete `.codepilot/memory/sessions.jsonl` to retry |
| Retry-approval prompt after 2 failed runs, but the failure is in an unrelated test | The target repo's own suite is failing on `main`; fix the baseline first |
| `MERGE CONFLICT` in Agent Logs | Someone changed the same file on the base branch; review it, then re-run |
| `Skipped reviewer ...: that account is the pull request author` | Expected when the token owner opened the issue |
| Headless mode takes a few minutes to stop after Ctrl+C (Windows) | Expected: it stops at the next poll (up to `CODEPILOT_POLL_INTERVAL_MINUTES`). Use the TUI (`q`) for an immediate stop |

More is in [`docs/troubleshooting.md`](docs/troubleshooting.md).
